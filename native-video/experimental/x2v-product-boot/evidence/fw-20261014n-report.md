# X2V 固件 20261014n：交付与机上验证（2026-10-14）

固件目录：`native-video/experimental/x2v-product-boot/dist/x2v-fw-20261014n/`，每个文件都按 `manifest` 里的 SHA-256 固定。

| 机上路径 | 作用 |
|---|---|
| `/system/etc/weston.ini`（hook 版） | 让 weston 加载 `x2v-boot-20261013c.so` |
| `/system/lib64/weston/x2v-boot-20261013c.so` | 开机启动名字最新的 `x2v_product_boot_*.sh` |
| `/system/etc/x2v/x2v_product_boot_20261014n.sh` | 机内总控：界面、录制、存储保护、片库 |
| `/system/etc/x2v/x2v_video_session_20261014m.sh` | 视频会话：进入、录制、停止、退出 |
| `/system/lib64/libx2v_prr_resident_20261014m.so` | 注入 camera-service 的录制核心（sha `6d985b6f…`） |
| `/system/bin/x2v_prr_play_20261013a` | 机内回放 |
| `gui/` | 视频界面（实验性功能菜单、格式选择、相册） |

## 安装（需要电脑，一次性）

```sh
cd native-video/experimental/x2v-product-boot
../../../.venv/bin/python deploy.py install   # 只新增文件，绝不覆盖不同内容的同名文件
../../../.venv/bin/python deploy.py hook      # 改 weston.ini；原厂副本存在 /system/etc/x2v/weston.ini.stock
../../../.venv/bin/python deploy.py status    # 应显示 "weston.ini hooked"
```

装好后不再需要电脑：开机自动启动；在原厂「驱动模式」弹窗里切到视频；用「实验性功能 › 格式」选 H.264、ProRes RAW HQ 或 CinemaDNG；快门开始和停止录制；回放键打开视频相册。片子存在 SSD 的 `X2V_RAW/` 下。

## 恢复

- 回到纯原厂：`deploy.py unhook` 写回原厂 weston.ini（会先核对 SHA），下次开机就是原厂相机。固件文件留在 `/system`，但不会被加载。
- 暂停而不卸载：建 `/blackbox/x2v-native-20261011/product/disable` 文件，boot 模块下次开机会跳过总控。
- 回退版本：删掉 `x2v_product_boot_20261014n.sh`，名字最新的 m 版就会接管。机上保留了 k、l、m 三个版本，可以回退。

## 本轮修复

1. **DNG 开头丢帧**（开机后第一段 60 s 片子，i、j、k、l 四个版本分别丢 3、3、1、1 帧，m 版 0 帧）
   - 一个原因是 H.264 代理编码器（`test_venc_e2`）启动、以及空闲后第一帧编码时，所有 NVMe 完成中断会停 70–610 ms。处理办法：进视频模式时就先拉起编码器；DNG 帧在代理出第一帧之后才开始，并用 4 KB 直写探测 SSD 是否恢复。
   - 另一个原因是开机后第一段片子的 3 个基础帧槽（每个约 22 MB）从未被访问过，第一次拷贝时才在相机回调里缺页，开头几帧拷贝变慢，加上 SSD 停顿，帧槽就不够用。现在在 `prep` 阶段（进入视频模式时）就预先访问这些帧槽。
2. **开机后相册为空**：总控在开机约 8 s 时写片库，而 SSD 要到 9.8 s 才挂载，所以开机后第一次录完之前相册都是空的。现在每 2 s 检查一次片子目录是否出现或消失，有变化就重建片库。
3. 之前已修好并在机上验证的：半按快门导致取景卡死（原厂半按时切换传感器，抢走视频流，现在被会话闸门接住）；取景的绿色、黄色横纹（ISP 预览每 96 行色度出现一条带，现在逐条带做增益校正）；ProRes RAW 高码率丢帧（改为 O_DIRECT 环形写入）。

## 机上验证（20261014m 录制核心 + 20261014n 总控）

| 测试 | 结果 |
|---|---|
| DNG 60 s，重启后第一段（两次） | 1433、1434 帧，0 丢，0 漏；写入最慢 101、88 ms（l 版 213 ms）；拷贝最慢 16 ms（l 版 49 ms） |
| DNG 20 s，不重启（3 次，l 版） | 465、478、478 帧，0 丢 |
| 三种格式依次录制 | H.264 337 帧、ProRes RAW 340 帧、DNG 344 帧（代理 354 帧），都是 0 丢，都进了片库 |
| 空间快满 | 22.8 s 后自动停止并保存（375 帧，0 丢，进了片库），屏幕提示"存储空间将满，录制已停止并保存" |
| 空间不足时开录 | 拒绝录制，提示"存储空间不足，无法开始录制" |
| 开机后的片库 | 42 段可播（36 段 ProRes RAW、4 段 H.264、2 段 DNG）；片子目录消失或出现时 2 s 内重建 |
| DNG 录制负载 | 4 核共占用 76%；写入约 419 MB/s（60 s 写了 25.06 GB）；录制中 MemAvailable 约 170 MB |

存储阈值：剩余不到 4096 MB 时自动停止，不到 8192 MB 时不让开始；可用 `product/storage_mb` 写入"<停止> <开始>"覆盖这两个值。

## 已知限制 / 未验证

- **没有做拔掉电脑后的整机验收**：需要你拔线后操作一遍。插着 USB 时，原厂会弹出"USB已连接"提示，第一次进视频会失败（rc 10）并自动重试，所以开机进入视频模式要 52–104 s。不插线时的开机时间还没测。
- 视频模式的取景是约 10 Hz 的预览图，不是 50 Hz 的显示层。
- DNG 按下快门后约 0.4 s 才开始出帧，代理视频从按下时就开始录。这 0.4 s 是用来避开编码器唤醒时 SSD 停顿的，停顿本身出在原厂编码器或硬件上，没有根治。
- 原厂 camera-service 每秒往 `/blackbox/.../video/service.log` 写 30–42 KB 的计时告警，总控在 16 MB 时截断。这会持续写 eMMC，暂时没有过滤（要改原厂日志路径，有风险）。
