# 当前对焦：原厂部分与我们的适配

原厂的主体识别与跟踪模型、AF 软件库、测距模块和镜头驱动仍在使用。我们没有重新训练识别模型，没有重刷 DSP 固件，也没有替换镜头马达的控制算法。但视频模式使用的输入和工作安排，与原厂拍照流程并不完全相同。

| 环节 | 当前分工 |
|---|---|
| 找到并跟住物体 | 调用原厂视觉服务和跟踪模型。我们提供视频画面、点击位置和启动/停止控制。 |
| 将跟踪位置送给 AF | 原厂有缓存读取机制。我们修正了接法，AF 现在按帧读取原厂跟踪统计，实测约 24 次/秒。 |
| 判断镜头应移到哪里 | 仍调用原厂连续 AF 控制器；当前视频适配以原厂 ToF 测距为主要依据。 |
| 最后把焦点修准 | 没有完整恢复拍照时等价的连续相位/反差测量链，不能把当前视频 AF 当作完整拍照 AF。 |
| 驱动镜头 | 仍由原厂镜头驱动执行，原有限位和马达控制保留。 |
| 视频交互 | 我们实现待机持续 AF、点击锁定、状态框、取消、丢失后清理及菜单/Playback/AF-MF 交接。 |

## 我们确实改过的对焦条件

1. 为在当前视频读出模式中工作，切换到原厂连续控制器，并跳过起始的拍照反差搜索。
2. 将原厂测距设为主要依据；当前没有证据证明视频中已持续得到拍照等价的相位/反差输入。
3. 将 ToF 峰值接受门槛从 80 放宽到 60；其他已知高门槛、原厂置信度计算和镜头限位保留。这可能使系统更愿意接受不够确定的距离结果，需要光学验证。
4. 对焦帧率适配为 24fps，并将视频待机及录制状态传给原厂控制器。
5. 当前 AFC 设置使用初始化后的一份快照；曝光或场景变化时哪些设置本应刷新，仍需核验。不能据此说 ISO 或实际曝光本身被固定。

这些改动超过了界面接入的范围。因此“原厂模型和硬件仍在用”不能推出“效果应与原厂拍照一样”。

## 关于 DSP

原厂硬件和视觉处理服务仍在使用，但对焦不是一个全部运行在 DSP 上的单独模型。当前可以直接看到 AF 决策和控制经过原厂 ARM 软件库。拍照时 DSP/ISP 提供的相位、反差等测量，是否在视频里完整、及时地送到控制器，是另一项独立问题，目前尚未建立等价链路。

## 对精度差距的工作假设

最近修正的是“AF 能否拿到正在跟踪的物体位置”。下一项应优先核对“测距拉到附近后，能否继续精确修正”，并检查曝光变化下输入和参数是否及时更新。还需对照测距区域与目标区域的空间映射。

这仍是待验证的解释。不能把失焦直接归因于原厂模型，也不能仅凭跟踪框稳定就判定光学对焦精度已经通过。
