# X2V 20261111b · 原厂跟踪接入与丢失后结束

适配 X2D II 100C，原厂固件 **1.3.16.2**。这是已装机的视频扩展存档，不是哈苏官方升级包。

本版保留用户认可的锁定速度和跟焦表现。原厂跟踪结果以约 24 次/秒送入原厂 AF；跟丢后停止本次跟踪、清除触摸选择状态，必须重新点击才能再次锁定。左上角使用半透明大号“取消跟踪”按钮。待机持续 AF、镜头 AF/MF 切换、菜单及 Playback 交接沿用现有实现。

永久入口为 `/system/etc/x2v/x2v_product_boot_20261111b.sh`，界面目录为 `/blackbox/x2v-native-20261011/gui-tracking-b`。原 `20261111a` 启动项保留。`files/` 保存本版及所依赖的版本文件；应按已有版本部署流程只安装缺少的新文件，不覆盖不同内容的旧目标。

## 已验证

- 用户确认原厂主体跟踪接入后的性能及锁定速度满意。
- 正常关机再开机后，实际从永久 B 启动项启动并进入 24fps 视频待机。
- 真正的目标丢失产生了 `stop_af → restore → unclaim`，没有进入自动搜索状态。
- 用户确认跟丢后行为、重新点击、菜单和 Playback 响应正常。
- 主机状态机通过 9 个案例，包括丢失后旧结果不能复活锁定、原生会话先结束的事件顺序。
- 主机 Qt 进行了 4,000 次文件读取，仅分配一个复用请求对象，并验证同一文件修改后能读到新内容。

## 尚未闭合

当前视频 AF 主要依据原厂 ToF 测距，拍照等价的连续相位/反差测量输入尚未建立。初始拍照反差搜索被跳过，ToF 接受门槛从 80 调为 60，并复用一份启动后的 AFC 配置快照。不同距离、曝光和镜头下的精度仍需继续验证。详见 [对焦分工](AF_PIPELINE.md)。

界面请求对象数已经有界，但机内约 155 秒观察中 GUI RSS 仍从 283,860 KiB 增至 304,512 KiB，期间没有换页。**不能据此宣称长期内存增长或卡顿已彻底解决。** 这项限制作为本版状态一并存档。

`receipt.json` 记录安装和接受情况，`evidence/` 保存精简实机证据。`source/af24/inputs/` 是当前 24fps 库的编译输入快照；其构建记录依赖相同版本的原厂 SDK/固件提取目录。`source/ui-tests/` 保存界面状态机和实际 Qt 请求复用测试。界面运行源码直接保存在 `files/blackbox/x2v-native-20261011/gui-tracking-b/`。
