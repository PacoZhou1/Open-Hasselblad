# 首个真实 USB 视频采集结果

日期：2026-10-11。相机 X2D II，固件 1.3.16.2，XCD 55V / v1.9.11。

## 已完成

通过工厂诊断通道调用原厂 set_live_view_extended，读取 USB interface 4 的数据端点 0x86，得到 LIVE/H264 报文。无需 Frida、进程挂接、固件刷写或启动配置修改。视频只保存在 Mac。

原厂 start_recording / stop_recording 已实测返回 Not implemented。因此本结果是原厂编码预览的电脑端录制，不能描述为机内独立录像已实现，也不能证明 Type-C DisplayPort/HDMI 监视器直出。

## 第二次采集（已完整验证）

目录：usb-preview/20261011-180543/

- 成片：x2d2-real-usb-preview.mp4。
- 100 帧，1300×970，H.264 High / Level 5.1，8bit YUV 4:2:0，BT.709 limited-range。
- 按 USB 时间字段解释，时长 3.320111 秒，平均约 30.12fps，容器平均码率约 25.51Mbps。
- 时间基于报文 offset 52 的 64 位字段，结合帧号及实机 50fps 属性按微秒解释；观察到约 20/40ms 间隔。该单位尚无厂商文档确认，帧号的 1/2 步进原因亦未最终确认，不能称为恒定 30fps 或无丢帧。
- 每个完整记录含 1024 字节包头，offset 12 表示总长度，offset 84 表示有效 H.264 长度。第二次输入无尾部残包。
- FFmpeg 完整严格解码成功；MP4 与原始 H.264 逐帧解码 MD5 完全一致，未重新编码图像；队列清空。
- 已查看首帧，是真实相机画面但未合焦。本次验证数据链路，不评价画质或对焦。
- 开始与停止接口均返回 Ok；用户确认此次屏幕没有再次报“无法向 Phocus 传输数据”。

## 首次报错与修正

第一次采集得到 161 帧可解码的真实视频，但接收循环先退出，再请求相机停止，屏幕出现 Phocus 传输失败；停止命令也返回异常，随后确认预览已关闭。尾部不完整记录被排除。

第二次把 USB 数据读取放入独立线程，在启动和停止命令期间持续排空传输，停止确认后才关闭接收。结果同时通过接口返回、文件验证和用户屏幕观察。该结果支持“停止阶段未及时消费 USB 导致异常”的判断，尚未取得原厂日志证明唯一根因。

两次均设置相机端有限时长的独立停止任务；第二次正常停止确认后撤销自己创建的停止任务。无新增相机文件。

## 结束状态

live_view_state=Off、transport=None、status=Initialised、exposure_status=None。camera-service=380、camera-gui=383、phocus=1096，与试验前相同。两份原厂服务启动配置哈希与官方提取物一致；/system 仍只读。ADB 保留用于后续调试。

## 本地入口

- usb_preview_capture.py：一次约 3 秒的受控 USB 预览采集，需设备处于预览关闭状态，严格核对实机服务哈希，持续读取到停止完成。
- decode_usb_preview.py <采集目录>：解析原始报文、按实测字段封装及完整解码/逐帧校验；使用 usb-preview/libx2v_host.dylib，该库来自附件原型 recorder.c 的 Mac 编译物。
- factory_session.py：只建立核实身份的工厂 USB 会话。

下一阶段仍需验证多次启停、较长持续采集、时钟和帧号含义；机内文件保存、UI、音频、高分辨率/高码率模式是后续独立工作。
